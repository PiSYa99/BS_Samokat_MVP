
## Что попробовать

1. На главной нажмите «Обновить» рядом с «Собрали для вас», чтобы получить другие варианты по истории выбранного профиля. Раскройте «Состав набора». В «Изменить состав» замените позицию, увеличьте количество или найдите ещё один товар. Добавьте набор в корзину. Совпадающие SKU суммируются с тем, что уже лежит в корзине.
2. Найдите товар через поиск или категорию. Добавьте его и оформите демозаказ. В профиле раскройте верхнюю запись истории. В ней сохранены количества, цены на момент оформления и итог. При следующем входе на главную модель увидит этот заказ.
3. В профиле нажмите «Сменить» и выберите Евгения или Диму. У каждого своя история, корзина и подборка.
4. Сравните «Обычный» и «С наборами» на главной или в профиле. У режимов отдельные корзины. Обычный режим позволяет пройти тот же путь покупки вручную. История завершённых покупок общая для обоих режимов одного человека.
5. Для сопоставимых замеров дайте участникам одно и то же задание и начните с одинаковой демоистории в отдельных базах. После пилотных покупок запустите сервер с новым путём базы, например `SAMOKAT_DB=runtime/round-2.sqlite3 .venv/bin/python -m uvicorn app:app --port 8765`. Это сохранит предыдущий эксперимент.

## Модель и данные

Предоставленный Python-код, веса, политика и снимок каталога находятся в `ml_v4/`. При запуске сервер загружает модель через `adapter_example.build_engine`. Модель v4 поддерживает 2 300 SKU с признаком eligible_for_simulation. Адаптер передаёт ей покупки этих SKU и их стоимость. В истории и сумме заказа сохраняются также непродовольственные товары.

Модель ранжирует товары по индивидуальной истории. При сборке наборов магазин учитывает совместные покупки и подбирает три разные составляющие одного завтрака, обеда, ужина или перекуса. Название соответствует выбранному сочетанию. На странице показываются две подборки без общих SKU. После исчерпания подходящих вариантов обновление заканчивается. Новый заказ учитывается при следующем расчёте.

Витрина читает все строки catalog.csv из архива `ml_v4/catalog.zip`. Четыре позиции с неподтверждённой ценой видны с пометкой «Цена уточняется». В `data/assortment.json` хранятся фотографии и оформление отдельных карточек. `data/profiles.json` содержит описания профилей. Модуль demo_history.py создаёт историю за предыдущие 12 месяцев до вчерашнего дня по московскому времени. При переходе с короткой истории заменяются стартовые заказы, а оформленные пользователем покупки сохраняются. Файл `runtime/shop.sqlite3` создаётся автоматически. Смена профиля служит демонстрационным переключателем.


## Фотографии

Все карточки используют локальные JPEG-фотографии. Для вариантов без подтверждённого снимка в витрине указано «Фото для примера». Упаковка, производитель или сорт на такой фотографии могут отличаться. Привязка к SKU хранится в [списке фотографий каталога](data/catalog-photos.json), ссылки на страницы и оригиналы — в [реестре источников](data/catalog-photo-sources.json). Первоначальные фотографии и обложка завтрака описаны [отдельно](data/photo-sources.json).

## Журнал эксперимента

[События в JSON](http://127.0.0.1:8765/api/metrics) содержат время UTC, идентификатор сессии, профиль и режим. Для выгрузки в файл:

```bash
curl -fsS http://127.0.0.1:8765/api/metrics -o experiment.json
```

| Событие | Данные |
|---|---|
| `shopping_started` | Создание корзины для профиля и режима |
| `cart_changed` | Состав до и после ручного изменения |
| `bundle_edited` | Добавление, замена, удаление или изменение количества, состав до и после. Записывается и для набора, который пользователь затем оставил |
| `bundle_added` | Исходный и добавленный состав, стоимость набора, признак редактирования |
| `checkout` | Номер заказа, итог в рублях, время сбора корзины и полное время сессии |

Для сравнения режимов используйте `active_build_seconds` у завершённых заказов. Браузер учитывает время видимой вкладки на главной, в каталоге, редакторе и корзине. Таймер приостанавливается в профиле, при оформлении и при скрытии вкладки. Пересекающиеся интервалы нескольких вкладок учитываются один раз. При прямом заказе через API без браузерных интервалов значение равно null. `duration_seconds` показывает календарное время от открытия корзины до подтверждения, включая перерывы. Стартовые покупки исключены из журнала эксперимента.

## API

Полные схемы запросов доступны в [OpenAPI JSON](http://127.0.0.1:8765/openapi.json). Суммы в рублях, количество в упаковках.

| Метод и адрес | Назначение |
|---|---|
| GET /api/catalog, GET /api/users | Каталог и демопрофили |
| GET /api/users/{uid}/orders | Заказы с количеством и ценой каждого SKU |
| POST /api/users/{uid}/sessions | Создать или восстановить корзину для ordinary или personal |
| GET /api/sessions/{sid}/recommendations | Прогноз v4 по текущей истории |
| GET /api/sessions/{sid}/recommendations/page | Текущие наборы, версия страницы и наличие следующих вариантов |
| POST /api/sessions/{sid}/recommendations/refresh | Следующая страница по переданной версии. Повтор запроса возвращает текущую страницу |
| GET, PATCH /api/sessions/{sid}/cart | Прочитать и обновить корзину |
| POST /api/sessions/{sid}/edits | Зарегистрировать правку в редакторе |
| POST /api/sessions/{sid}/visits | Обновить интервал времени сборки |
| POST /api/sessions/{sid}/checkout | Сохранить заказ и закрыть корзину одной транзакцией |
| GET /api/metrics | Журнал для анализа |

PATCH принимает `revision` и словарь `items` в формате SKU → количество. Для одиночных товаров передаётся полный новый состав корзины. При передаче `offer` сервер добавляет присланный набор к текущему составу. При конфликте версий сервер возвращает 409. Повторное оформление одной сессии возвращает квитанцию уже созданного заказа.

## Проверка

```bash
.venv/bin/python -m unittest discover -q
.venv/bin/python -m unittest discover -s ml_v4 -q
```

Проверки магазина используют временную SQLite-базу. Они охватывают индивидуальные прогнозы, каталог и изображения, изоляцию пользователей и режимов, повторное открытие корзины, конфликт версий, смешанную корзину, повтор оформления, журнал и поступление покупки в новую историю модели.
